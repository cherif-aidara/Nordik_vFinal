1. INTRODUCTION ET CONTEXTE
================================================================================

Le projet Nordik Adventures est un système PGI (Progiciel de Gestion Intégré) 
développé pour une entreprise fictive de commerce électronique spécialisée dans 
les équipements de plein air. Ce projet fait suite au TP#2 qui consistait en 
l'analyse et la modélisation du système.

Le TP#3 consiste à développer un site web transactionnel fonctionnel qui met en 
œuvre les processus, modules et règles d'affaires définis dans le TP#2. Le système 
doit démontrer le fonctionnement intégré du PGI à travers une interface web 
dynamique.

OBJECTIFS DU PROJET :
- Mettre en œuvre les règles d'affaires et relations de données du TP#2
- Démontrer l'intégration des composantes essentielles d'un e-commerce
- Offrir une expérience utilisateur simple, fluide et logique
- Créer un prototype fonctionnel (Proof of Concept)

TECHNOLOGIES UTILISÉES :
- Framework : Django (Python)
- Base de données : SQLite (développement) / MySQL (production possible)
- Frontend : HTML5, CSS3, JavaScript
- Authentification : Django Authentication System
- Interface Admin : Django Admin

================================================================================
2. ARCHITECTURE TECHNIQUE
================================================================================

ARCHITECTURE GLOBALE :
Le projet suit une architecture MVC (Model-View-Controller) adaptée à Django :
- Models : Définition des données et règles métier (django.db.models)
- Views : Logique de traitement des requêtes (views.py)
- Templates : Présentation des données (templates/)
- URLs : Routage des requêtes (urls.py)

STRUCTURE EN MODULES :
Le système est organisé en 4 modules Django interconnectés :

1. Module "pgi" (Application principale)
   - Tableau de bord
   - Authentification (login, register, logout)
   - Navigation principale
   - Paramètres

2. Module "stocks" (Gestion des produits et stocks)
   - Catalogue produits
   - Fiche produit détaillée
   - Gestion des stocks
   - Alertes de réapprovisionnement

3. Module "finances" (Gestion financière et facturation)
   - Tableau de bord financier
   - Gestion des factures
   - Gestion des dépenses
   - Trésorerie

4. Module "clients" (Gestion de la relation client)
   - Panier d'achats
   - Processus de commande (checkout)
   - Historique des commandes
   - Évaluation de satisfaction
   - Historique d'activités client

5. Module "common" (Modèles communs)
   - Modèles partagés (TimeStampedModel)

INTÉGRATION FRONT-END / BACK-END :
- Le backend Django traite toutes les requêtes HTTP
- Les templates Django génèrent le HTML dynamiquement
- Les formulaires utilisent la protection CSRF de Django
- Les sessions sont gérées par Django
- Les fichiers statiques (CSS, JS) sont servis par Django

INTÉGRATION BASE DE DONNÉES :
- ORM Django pour toutes les opérations sur la base de données
- Migrations Django pour la gestion du schéma
- Relations ForeignKey, OneToOne, ManyToMany gérées par Django
- Validation des données au niveau modèle et formulaire

4.4 MODULE CLIENTS (Gestion de la relation client)
---------------------------------------------------

FONCTIONNALITÉS :
- Panier d'achats avec calcul automatique des taxes
- Processus de commande (checkout)
- Historique des commandes client
- Évaluation de satisfaction (1-5 étoiles)
- Historique d'activités client (pour employés)
- Gestion automatique du statut client

VUES PRINCIPALES :
1. cart_view(request)
   - Affichage du panier du client connecté
   - Liste des articles avec quantités
   - Modification des quantités
   - Retrait d'articles
   - Calcul automatique : sous-total, TPS, TVQ, total
   - Bouton "Passer la commande"

2. add_to_cart(request, product_id)
   - Ajoute un produit au panier
   - Vérifie la disponibilité du stock
   - Crée ou met à jour le CartItem
   - Redirection vers le panier

3. remove_from_cart(request, item_id)
   - Retire un article du panier
   - Supprime le CartItem

4. update_cart_item(request, item_id)
   - Met à jour la quantité d'un article
   - Valide la quantité disponible

5. checkout(request)
   - Processus de commande complet :
     * Crée une ClientOrder
     * Crée les OrderLineItem depuis le panier
     * Calcule le total
     * Génère automatiquement une Invoice
     * Diminue les stocks (via signal)
     * Vide le panier
     * Redirige vers la confirmation

6. my_orders(request)
   - Historique des commandes du client connecté
   - Affichage des statuts
   - Liens vers les factures
   - Bouton d'évaluation pour les commandes complétées

7. rate_order(request, order_id)
   - Interface d'évaluation de commande
   - Système d'étoiles (1-5)
   - Commentaire optionnel
   - Crée un OrderRating

8. client_activity_history(request, client_id)
   - Historique complet des activités d'un client
   - Visible uniquement par les employés (is_staff)
   - Timeline des actions (commandes, emails, appels, etc.)

MODÈLES :
- Client : Informations clients avec statuts (Prospect, Actif, Fidèle, Inactif)
- ClientOrder : Commandes clients avec statuts
- OrderLineItem : Lignes de commande
- Cart : Panier d'achats
- CartItem : Articles dans le panier
- OrderRating : Évaluations de satisfaction
- ClientActivityLog : Historique horodaté des activités
- ClientInteraction : Interactions avec les clients

URLS :
- /clients/ → Liste des clients (admin)
- /clients/panier/ → Panier d'achat
- /clients/panier/ajouter/<id>/ → Ajouter au panier
- /clients/panier/retirer/<id>/ → Retirer du panier
- /clients/panier/modifier/<id>/ → Modifier quantité
- /clients/commander/ → Checkout
- /clients/mes-commandes/ → Historique commandes
- /clients/commande/<id>/evaluer/ → Évaluer commande
- /clients/client/<id>/historique/ → Historique activités (employés)

6. VUES ET LOGIQUE MÉTIER DÉTAILLÉE
================================================================================

6.1 PROCESSUS D'AUTHENTIFICATION
---------------------------------

INSCRIPTION (register) :
1. L'utilisateur remplit le formulaire (nom, email, mot de passe, etc.)
2. Validation côté serveur :
   - Email unique
   - Mots de passe identiques
   - Longueur minimale du mot de passe
3. Création d'un User Django :
   - Username généré depuis l'email
   - Email et mot de passe hashés
4. Création d'un Client associé :
   - Statut initial : PROSPECT
   - Informations complémentaires (téléphone, adresse)
5. Connexion automatique de l'utilisateur
6. Redirection vers le tableau de bord

CONNEXION (login_view) :
1. L'utilisateur saisit email et mot de passe
2. Recherche du User par email
3. Authentification avec Django (authenticate)
4. Si succès : login() et redirection
5. Si échec : message d'erreur

DÉCONNEXION (logout) :
- Utilise Django LogoutView
- Redirection vers la page de connexion


6.2 PROCESSUS D'ACHAT COMPLET
-------------------------------

ÉTAPE 1 : NAVIGATION CATALOGUE
- L'utilisateur (connecté ou non) parcourt le catalogue
- Recherche et filtres disponibles
- Affichage des prix et stocks

ÉTAPE 2 : CONSULTATION FICHE PRODUIT
- Clic sur un produit → product_detail
- Affichage de toutes les informations
- Si connecté : bouton "Ajouter au panier"
- Si non connecté : invitation à se connecter

ÉTAPE 3 : AJOUT AU PANIER
- Clic sur "Ajouter au panier" → add_to_cart
- Vérification :
  * Utilisateur connecté
  * Stock disponible
- Création ou récupération du Cart du client
- Création ou mise à jour du CartItem
- Calcul automatique des totaux
- Redirection vers le panier

ÉTAPE 4 : GESTION DU PANIER
- Affichage de tous les articles (cart_view)
- Modification des quantités (update_cart_item)
- Retrait d'articles (remove_from_cart)
- Calcul automatique en temps réel :
  * Sous-total
  * TPS (5%)
  * TVQ (9.975%)
  * Total TTC

ÉTAPE 5 : CHECKOUT
- Clic sur "Passer la commande" → checkout
- Vérifications :
  * Panier non vide
  * Stock disponible pour tous les articles
- Création de la ClientOrder :
  * Génération du numéro de commande unique
  * Date de commande = aujourd'hui
  * Statut initial : RECEIVED
  * Calcul du total
- Création des OrderLineItem :
  * Un par article du panier
  * Quantité et prix unitaire
- Génération automatique de l'Invoice :
  * Numéro de facture lié à la commande
  * Date de facture = aujourd'hui
  * Échéance = +30 jours
  * Statut : PENDING
  * Calcul TPS/TVQ automatique
- Création des InvoiceLineItem :
  * Un par ligne de commande
- Déclenchement des signaux Django :
  * Mise à jour du stock (diminution)
  * Création de StockMovement
  * Création de ClientActivityLog
  * Mise à jour du statut client (Prospect → Actif)
  * Message de bienvenue si première commande
- Vidage du panier
- Redirection vers la confirmation

ÉTAPE 6 : CONFIRMATION ET SUIVI
- L'utilisateur peut voir sa commande dans "Mes commandes"
- Accès à la facture générée
- Possibilité d'évaluer la commande après réception


6.3 CALCULS AUTOMATIQUES
-------------------------

CALCUL DU PANIER (Cart) :
- subtotal = somme(quantity × unit_price) pour tous les CartItem
- tps = subtotal × 0.05
- tvq = subtotal × 0.09975
- total = subtotal + tps + tvq

CALCUL DE LA FACTURE (Invoice) :
- amount = somme(quantity × unit_price) pour tous les InvoiceLineItem
- tps = amount × 0.05
- tvq = amount × 0.09975
- total_amount = amount + tps + tvq

CALCUL DE LA MARGE BRUTE (Product) :
- gross_margin_percent = ((sale_price - purchase_cost) / sale_price) × 100

CALCUL DU STATUT CLIENT :
- Prospect → Actif : première commande
- Actif → Fidèle : 5 commandes OU 3000$ dépensés


6.4 VALIDATIONS
---------------

VALIDATION PRODUIT :
- SKU unique (au niveau base de données et clean())
- sale_price > purchase_cost (dans clean())
- Quantités positives

VALIDATION PANIER :
- Stock disponible avant ajout (dans add_to_cart)
- Quantité ≤ stock disponible (dans update_cart_item)
- Panier non vide avant checkout

VALIDATION COMMANDE :
- Stock disponible pour tous les articles (dans checkout)
- Client connecté
- Panier valide

VALIDATION FACTURE :
- Montants positifs
- Calculs TPS/TVQ automatiques

9. SIGNAUX DJANGO ET AUTOMATISATION
================================================================================

9.1 PRINCIPE DES SIGNAUX
-------------------------

Les signaux Django permettent d'exécuter du code automatiquement lors d'événements 
spécifiques (création, modification, suppression d'objets). Cela permet de séparer 
la logique métier de la logique de présentation.

FICHIER : clients/signals.py

9.2 SIGNAUX IMPLÉMENTÉS
-----------------------

SIGNAUX 1 : HANDLE_CLIENT_ORDER_SAVE
Déclenché : Lors de la création ou modification d'une ClientOrder

Actions automatiques :
1. Mise à jour du statut client (Prospect → Actif)
   - Si première commande : status = ACTIVE
   - Création d'un message de bienvenue

2. Création d'une activité client
   - ClientActivityLog avec type ORDER
   - Description avec numéro de commande et montant

3. Création d'une facture associée
   - Invoice avec numéro lié à la commande
   - Date d'échéance = +30 jours
   - Statut PENDING
   - Création des InvoiceLineItem depuis les OrderLineItem

4. Diminution du stock
   - Pour chaque produit vendu : quantity_in_stock -= quantity
   - Création d'un StockMovement (type OUT)
   - Raison : "Vente - Commande #XXX"

5. Mise à jour vers statut Fidèle
   - Si total_orders >= 5 OU total_spent >= 3000
   - status = LOYAL
   - Création d'une activité

Code clé :
@receiver(post_save, sender=ClientOrder)
def handle_client_order_save(sender, instance, created, **kwargs):
    if created:
        # Toutes les actions automatiques
        ...

SIGNAUX 2 : HANDLE_INVOICE_SAVE
Déclenché : Lors de la modification d'une Invoice

Actions automatiques :
1. Mise à jour du statut de commande
   - Si facture payée (status = PAID)
   - Commande associée → status = PAID
   - Création d'une activité client

Code clé :
@receiver(post_save, sender=Invoice)
def handle_invoice_save(sender, instance, created, **kwargs):
    if instance.status == Invoice.STATUS_PAID:
        # Mise à jour commande
        ...

9.3 CONFIGURATION DES SIGNAUX
-----------------------------

Les signaux doivent être importés dans apps.py pour être activés :

FICHIER : clients/apps.py
class ClientsConfig(AppConfig):
    def ready(self):
        import clients.signals  # Import des signaux
